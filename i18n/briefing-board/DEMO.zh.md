# 工程简报板 — 我们的示范片

这只是众多可能中的一个例子。不要照搬它的故事、结构、镜头、道具或时间安排。

示范片：*The Ship Decides*（船说了算，40.0 s）· `briefing-board.mp4` · 源文件在 [`demo/`](demo/)

一条 1,000 m 宽的河需要一座桥。第一个直觉——从岸到岸一路立桥墩——在一艘集装箱船撞上其中一个桥墩的瞬间就被盖章否决。新规矩：航道里不立墩，一跨过河。四种桥型按同一比例画出来，逐个对照河宽受检。河提出了问题；船定下了跨度。

## 故事与结构

形状：一场很早就出现转折的淘汰赛。钩子（0–1 s）：河宽在最初四分之一秒内“啪”地横贯画面。铺垫（1–8 s）：“1,000 米”，一座一墩接一墩的梁桥横跨过去。转折（8 s）：近乎静默一秒之后，船碰到中间的桥墩，一个红色印章落下。发展（11–27 s）：写下规矩，桥墩弹掉，一把钢尺从岸到岸铺下；虚线投影线把两岸向下引到一个立面“试验台”，四张桥梁照片一张接一张落在上面，每张落下时摄影机都凑近迎接，然后在一个停留的画面里接受评判：画面里有整座桥、两条岸线（1,000 m 的“门”）、按其最大主跨纪录画出的尺寸线，以及在摄影机停稳之后落下的判定。每个评判画面都比上一个更宽，所以“变宽”本身就是节奏：斜拉桥的线刚刚爬过对岸，悬索桥的线则猛冲过去，把摄影机都甩开了。结尾（32.8–40 s）：低到水线处，一艘侧视的集装箱船从远处桥塔后面驶出，从悬索桥的跨下穿过；半秒房间底噪；然后是唯一的一次拉镜，从船开始，一直拉到整面墙，结论“船决定跨度”写在结果旁边。最后一帧就是海报。

为什么契合这种风格：一面连续的墙上，上方是平面图（俯视的船、河、过河方案），下方是立面图（侧视的桥），两者之间用投影线相连——这是真实的制图规范，所以俯视的船和侧视的桥能共处一块板而不破坏几何关系。同一艘船出现在两种视图中：在平面图里是问题，在立面图里是答案。用到的原生手法：可数的磁铁、印章、擦成残影、实物答案（钢尺）、投影线、沿尺寸线运镜（四次）、主体穿过答案、引线指向结论，以及作为招牌镜头的整面墙揭示。

## 声音结构

- 120 BPM，4/4，D 小调 → 揭示时转 D 大调。乐器：电贝斯（八分音符音型），MuldjordKit 底鼓/军鼓/踩镲，响棒，沙锤，低音铜管重音（长号、大号、圆号），定音鼓，大鼓（gran cassa），镲片，管钟，钟琴，颤音琴。没有钢琴，没有弦乐铺底。
- 弧线：钩子（Dm 铜管重音、低音通通鼓、随“啪”的线条在 0.25 落下的底鼓）→ 律动 A → 低通下潜 → **7.0–8.0 静默** → 印章：Dm 铜管重音 + 定音鼓 + 大鼓 → 半速（延长的 D，低音通通鼓）→ 规矩写下时律动 A 重建 → 试验台段落用律动 B（整套鼓），每次照片落下有一个按该小节和弦的铜管重音，每次划线配一声刺耳的长号（D + E♭）→ 斜拉线爬行：贝斯以八分音符从 G1 半音上行到 G2，伴随沙锤渐强 → “刚好够”：两个圆号音 → 军鼓十六分音符推进到悬索桥的线（A，属音，落在照片落下时）→ 线条落定：镲片 + 明亮的 B♭ 和弦（VI 级）→ 圈出时一对颤音琴音 → 最后一条线和船出现时，贝斯全音符加柔和的长号五度 → **35.25–35.75 静默** → 揭示：调到 D 的船笛（根音和五度）加上 D 大调铜管和弦、定音鼓和管钟 → 结论随圆号旋律 A–F♯–E–D–A 写出 → 墙面停稳时钟琴 D–F♯–A–D。
- 卡点：每次落下、钉磁铁、盖章、箭头、划线和名牌都卡在十六分音符网格上（`tools/cuecheck.py`：27/27，误差 0 ms）。
- 拟音（程序化生成，`audio/mix.py`）：按笔画长度缩放的毡头笔吱吱声、笔尖轻点、按桥墩调音高的磁铁咔嗒声、每次照片落下后两声钉磁铁的咔嗒、吸盘啵声、照片落下声（板子闷响 + 纸张拍打，悬索桥那张更重）、钢尺的余音、橡皮擦的毡擦声、橡皮印章、船笛（远和近）、柴油机轰鸣、水波拍岸、呼啸声、带远处车流的房间底噪。
- J-cut：5.75 的汽笛早于俯视的船出现；32.0 的汽笛早于侧视的船从桥塔后驶出。L-cut：橡皮擦声延续到移入试验台的运镜中；揭示时的汽笛贯穿整个拉镜。
- 混音：音乐比人声低约 9 dB 并做闪避；拟音在语音下闪避；房间底噪（右边是空调，左边是窗外车流）比人声低约 20 dB，从不闪避；静默段用门限压到只剩房间底噪；整合响度 −14 LUFS。
- 人声：Kokoro `af_heart`，九句；数字在 TTS 中拼写成单词，在字幕中写成阿拉伯数字。

## 色板与道具

- 板面 6,400 × 3,600 板面像素（16:9，所以最后的拉镜正好填满画面）；搪瓷白 `#F3F1EB`；墙 `#8F8B83`；墨色：石墨 `#23272E`，蓝 `#1F4FC8`，红 `#D33A21`，水面排线 `#5F86DA`，制图灰 `#6C727B`。
- 平面图（左上）：河宽 1,240 px = 1,000 m，夹在两条蓝色河岸之间，岸上是灰色地面排线；上方写“1,000 米”；过河方案用七块石墨色磁铁；俯视的船缩放到 500 px（约为真实比例）；印章“否决”（Noto Sans SC 900，带斑驳的红色）。规矩“新规矩”用红色加下划线，“航道不立墩”用石墨色（LXGW Marker Gothic）。钢尺：拉丝钢材带刻线，两端各一块磁铁。
- 立面图（左侧三分之二）：投影线为蓝色虚线；四行按比例缩放，使每个主跨都是其纪录长度，比例为每米 1.24 px（330、600、1,208、2,023 m）；每张照片用两块磁铁固定；每个箭头末端下方有一个标签块：名牌（Noto Sans SC 700，78 px）和蓝色马克笔写的数字（100 px），名牌按数字实测宽度摆放，两者永不相碰。侧视的船长 340 px（约为真实比例），在一条手绘的水线上。斜拉桥是一张单塔照片镜像拼合而成，悬索桥的主跨被拉伸 ×1.7（见 `demo/CREDITS`）。
- 右侧三分之一（揭示之前从不入镜）：四张带磁铁的照片（悬索桥、斜拉桥、拱桥，以及抹掉了文字的侧视船），一张来源卡（“数据来源”），两张写着算式的便利贴（1,208 − 1,000 = 208；2,023 ÷ 1,000 ≈ 2），一张不带数字的通航净空小草图，右侧中部的结论“船决定跨度”（400 px，“船”字为红色）带一条从圈出的 2,023 引来的引线，以及片尾卡。
- 字幕：磨砂条，中文 Noto Sans SC 500 42 px 在上，英文 Archivo 500 29 px 在下，左侧一个蓝色勾标；每条字幕都经测量保证每种语言只占一行（`tools/subcheck.mjs`）。

## 制作说明

```
demo/
  index.html            the page: fonts, setScene / render / TEXTS / SUBCHECK / RESCHECK
  kit/board.js          the renderer (style engine)            kit/batch.mjs   stills from scene JSON
  kit/objects/          cut-outs + meta (anchors L/R for bridges, bow/stern for the ships)
  kit/tools/            prep_object.py, sky_key.py, mirror_span.py, stretch_span.py, redraw_stays.py,
                        redraw_suspension.py, repair_hangers.py, clean_lettering.py, ship_anchors.py,
                        make_print.py, rebuild_objects.sh; fetch_fonts.py, fetch_sources.py, kit_env.sh
  scenes/_gen_film.py   the film as data → scenes/film.json, audio/cues.json
  audio/lines.json      narration (Kokoro)          audio/mix.py   score, foley, voice, mix
  tools/                camcheck.mjs + camplot.py, rescheck.mjs, subcheck.mjs, cuecheck.py, rhythm_report.py, final_asr.py
  sources/              candidates/candidates.json (every photo looked at: URL, author, licence, evidence;
                        the six used ones with sha256); photos, masks and derived/ are downloaded or rebuilt
```

1. `sh demo/build.sh`（库已用 `setup.sh deps voice music` 配置好）：抓取 git 中没有保存的东西——来自 Google Fonts 的字体（`fetch_fonts.py`：Archivo 和 IBM Plex Mono 来自 github.com/google/fonts，CJK 子集通过 CSS API 获取），来自 Commons 的六张照片（`fetch_sources.py`，约 470 MB），一个私有的 `demo/.venv`，内含 onnxruntime 和 BiRefNet 模型（`kit_env.sh`，约 970 MB，除非已缓存），语音模型以及 freepats / vsco2ce / vcsl 采样——并重新抠出各个物件（`rebuild_objects.sh`）；然后依次是语音检查 → 场景 → 卡点检查 → 阅读检查 → 摄影机检查（含评判画面）→ 分辨率检查 → 事件 → 渲染（960 帧，5 个 worker）→ 混音 → 字幕（+ 单行检查）→ 合成（−14 LUFS，颗粒 1）→ 海报和风格帧 → 节奏报告 → 对最终混音做语音检查 → 摄影机轨迹图。
2. 物件：`sh demo/kit/tools/rebuild_objects.sh` 以照片的原始分辨率重新生成每个抠图（BiRefNet 遮罩缓存在 `sources/masks/`；重新计算的遮罩可能与我们的差一两个像素）。
3. 静帧和缩略图：写一个 `extends` `scenes/film.json` 的场景 JSON，带上自己的 `cam` 和 `t`，用 `node demo/kit/batch.mjs` 渲染。

与桥梁相关的选择：每次照片落下，镜头都凑近在桥塔塔顶、拱肋、吊杆或墩脚上迎接；斜拉索、主缆和吊杆按照片中实测的位置重绘成干净的线条。与本示范片相关的坑：第一版剪辑紧贴着每条尺寸线运镜，从未完整展示斜拉桥或悬索桥；观众搞不清在检验什么（“太快了”）。解决办法是为每座桥设一个评判画面，停留住，每次更宽，旁白和判定都放在停留期间。在运镜过程中才首次瞥见的文字没有通过阅读检查，所以每个标签块都钉在摄影机停留的位置，每一新行都和上一行的结果一起取景。最初的抠图被缩小过，近景又把它们放大（船变成了马赛克）；现在每个物件都以全分辨率抠出，`rescheck.mjs` 限制每次缩放。用抠像得到的斜拉索变成了阶梯状，拱桥的吊杆在山的背景中消失了；现在斜拉索和悬索都经测量后重绘，拱桥吊杆一直延伸到桥面。固定偏移的名牌会和较宽的数字重叠；现在按数字实测的前进宽度摆放。拉伸过的悬索桥照片最多只能到 z 1.38，所以它落下时的近景放在没有被拉伸的近处桥塔上。照片里的悬索桥具有 500 m 跨度的比例；如果等比缩放到 2,023 m，桥塔会高得离谱，所以只拉伸主跨。一块路牌、一个水位标尺、一个船名和集装箱标志都被去掉了（文字）。桥墩磁铁的咔嗒声盖住了旁白里的“piers”；已调低。
