# 16-bit 像素 RPG — 我们的演示片

这只是众多可能中的一个示例。请勿照搬它的故事、结构、镜头、道具或时间安排。

演示片：*The Last Save Point*（最后的存档点）（54.5 s）· `pixel-rpg.mp4` · 源文件见 [`demo/`](demo/)

一部 30–60 秒的短片：一位孤独的勇者站在存档水晶前，穿越三个色深时代回忆起他失去的同伴，然后推开了那扇巨门。

## 故事与结构

世界以 **320×180 原生像素**绘制，用最近邻缩放 ×6 到 1080p。每种颜色都来自一个**有限的索引色板**。渐变是**有序抖动**，而不是混合。角色是约 22×34 px 的**精灵图**，只用少数几帧动画。故事以游戏的方式讲述：通过**带头像的对话框**、**菜单**、**状态栏**、**战斗信息**和**存档文件**。

它*不是* HD-2D（没有景深，没有泛光，没有实时光照），*不是* CRT 怀旧（没有扫描线，没有颗粒），也*不是*戏仿。它认真地把游戏系统当作一种表达情感的语言。

绝不使用现有游戏的名称、角色、UI 边框、字体、标志、旋律或音效。学习语法，而不是素材。

选择那些**由游戏自身系统承载情感**的故事。演示片用了以下原生能力，最强的那几个（色板崩塌和色彩涌回）放在情感高潮处。

| 原生能力 | 故事中的用法 |
|---|---|
| **色板 = 情感** | 因为图像是索引色，你可以在一帧之内替换整个色板。记忆、悲伤、希望可以真的就是色深。在演示片中：越久远的记忆颜色越少（16-bit → 8-bit → 4 色）。失去之后的当下是**褪色**的。记忆的崩塌是色板**每个节拍下降一级**。希望是完整色板**通过一道有序抖动波涌回**。 |
| **受保护的颜色** | 让少数几个色板索引不受任何色板效果影响。一个永不褪色的红色物件（一条围巾）就成了贯穿全片的线索，也是跨时代的完美**匹配剪辑**。 |
| **游戏 UI 作为叙述** | 存档文件 = 一份记忆清单（选择 *NEW FILE* = 拒绝覆盖它们）。队伍列表中一个变灰的名字 = 死亡，无需一个字。"No inn will ever heal it"（没有哪家旅店能治好它）= 用这一媒介自己的词汇说出悲伤。 |
| **文本框与提示音** | 对话框*就是*字幕。一个没有配音、只有文字提示音的角色，读起来就像一个如今只存在于文字中的人。 |
| **时代切换** | 同样的角色用更老的硬件重绘：半分辨率下的 4 级灰阶、13 色 8-bit 色板、完整的 16-bit。免费的时间旅行。 |
| **类型化转场** | 温柔的回忆用马赛克进出。**遇敌漩涡**撞进危险。高潮用白闪。 |

改编任何题材：找到藏在其中的**游戏系统**。一次产品发布是获得一件新道具（凯旋音效、道具框、属性对比）。一次告别是一个永不被覆盖的存档。一段职业生涯是一个升级画面。一座城市是一张带存档点的大地图。

**45–60 s 的弧线：**孤独（安静、褪色、长卷轴）→ 温暖（一段回忆）→ 失去（系统崩坏）→ 决心（系统以全彩恢复）→ 一张同时也是游戏提示的片尾卡（*CONTINUE ▶*）。

## 镜头

| 节拍 | 摄影机 |
|---|---|
| 开场 | 穿过柱廊的长横向卷轴，勇者很小（画面高度的 1/6），四层视差，前方有一个彩色物件 |
| 菜单 | 固定画面，UI 在左侧三分之一，勇者和道具在右侧可见 |
| 温暖的回忆 | 全景，静止或缓慢摇镜；角色在天空或篝火前显得很小 |
| 战斗 | 经典侧视：敌人在左，队伍在右面朝左，UI 窗口在下方，信息窗口在顶部 |
| 失去 | 停留在画面上。色板崩塌期间不剪切、不移动 |
| 纪念碑 | 沿一扇三屏高的巨门**按整像素向上俯仰**到玫瑰窗，停留，再俯仰回来。全片唯一令人难忘的运镜 |
| 高潮 | 门槛处的背影，光洒在地上，颜色从勇者身上向外涌出 |

- 输出 24 fps。精灵以 **8 fps**（行走）到 **12 fps**（火焰、KO 闪烁）步进。摄影机和视差**逐帧**以整像素移动。行走速度 30 px/s ≈ 每帧 1.25 px。
- 游戏原生表演：向前跳一步再行动，举杖施法姿势，受击后退，下跪，然后 **KO 闪烁**（12 fps 亮/灭）并消失。呼吸 = 肩膀上抬 1 px，持续 0.6 s。
- UI 运动：窗口在 0.3 s 内滑入（缓出，整像素）。手形光标以 4 fps 上下浮动 1 px，**在角色犹豫时停止浮动**。文字以 38–40 字符/s 打出（8-bit 为 30），打完后 ▼ 以 3 Hz 闪烁。
- 转场：**缩略图展开 + 马赛克**（块大小 10 → 1，历时 0.75 s）；**马赛克交叉**（1 → 16 → 1，历时 0.8 s，在峰值处切换色板）；**遇敌漩涡**（极坐标扭曲按 `s^1.6` 增长，马赛克，Bayer 溶解到白，0.8 s）；**屏幕震动** 3–2–1 px，历时 8 帧；**色板分级淡变**（4 级），绝不用 alpha。

## 配乐结构

- **音乐**：原创芯片音乐（12.5/25/50% 方波、4-bit 三角波、LFSR 噪声、波表）。一个动机以**地域变奏**的形式贯穿每个段落。音乐的保真度跟随色深：
  - 4 色：单声道，4-bit 音量阶梯，11 kHz 采样保持；
  - 8-bit：类 NES，单声道；
  - 16-bit：立体声加 SNES 风格回声（3 个抽头约 180/270/370 ms，反馈 0.35–0.45，回路内低通约 3 kHz）；
  - 当下：同样的音乐，但被闷住（LP 2.2 kHz）。
  色板崩塌期间，音乐每一步失去一层：和声，然后回声和立体声，然后贝斯，然后只剩一个方波音，然后在图像到达当下的灰色时恰好有**一拍静默**。Boss 前奏是动机的小调版本；完整乐队在颜色涌回的那一小节进入。片尾卡解决了开场停在属音上的乐句。
- **拟音**，全部合成，并按场景所在时代做降比特处理：光标/选择提示音，文字提示音（同伴的更高，5-bit），带回声的石地脚步声，篝火噼啪，结界微光（三角波琶音），蓄力（上升方波 + 噪声），爆炸（扫频低通噪声 + 48 Hz 重击，降到 6-bit），HP 递减滴答，KO 闪烁，每个色板阶梯的**比特下降**（每次更低更粗），存档滴答，开门摩擦（棕噪声 + 调幅吱嘎），火把点燃，反向渐强。
- **唯一的有机声音**：勇者在门前的呼吸，带通噪声，不做降比特。它在最后一刻让他成为一个人。
- **静默**：爆炸之后（真正的零，回声尾音也被切掉），以及进入当下前的那一拍。
- **人声**：Kokoro `bm_george`，语速 0.9，第一人称，5 句短台词。人声下音乐压低约 −7.5 dB（60 ms 起音，350 ms 释放）。混音到 −14 LUFS，**grain 0**。

## 色板与道具

- **分辨率与缩放**：原生 320×180 索引帧缓冲（色板索引的 `Uint8Array`）。通过**查找表**（索引 → RGB）呈现，并以最近邻缩放 ×6。所有东西，包括文字，都画在帧缓冲里。摄影机移动是**整像素**；每一层视差各自取整偏移。
- **主色板**：ENDESGA-32（`#be4a2f #d77643 #ead4aa #e4a672 #b86f50 #733e39 #3e2731 #a22633 #e43b44 #f77622 #feae34 #fee761 #63c74d #3e8948 #265c42 #193c3e #124e89 #0099db #2ce8f5 #ffffff #c0cbdc #8b9bb4 #5a6988 #3a4466 #262b44 #181425 #ff0044 #68386c #b55088 #f6757a #e8b796 #c28569`），加上任何色板效果都不会碰到的**受保护副本**（围巾红 `#e43b44/#a22633/#f6757a`，水晶青 `#2ce8f5/#0099db/#ffffff/#124e89`）。
- **色深表**（全部由主色板计算得出）：
  - *16-bit*：恒等映射。
  - *8-bit*：映射到 15 色中最接近的颜色 `#000000 #fcfcfc #a4a4b8 #58587c #1c2c8c #3c7cfc #94e0fc #b8141c #fc7454 #fcb81c #8c4c1c #2c9c2c #fcd8a8 #0c4c18 #4c2410`。它需要一个深绿和一个深棕，否则夜晚的草地会变蓝。
  - *4 色*：固定亮度阈值（<60, <115, <175）→ `#1f2a1c #4b5e3a #93a263 #d6dba6`。用四个代表索引（墨 / 板岩 / 钢 / 白）绘制 4 色场景，让每个像素都落在预定的色阶上。以 **160×90** 渲染再放大一倍。
  - *褪色*：`lum^0.8 × 7` → 7 种蓝灰 `#0e0d17 … #c3c9d6`。**不要**按排序映射：排序映射会把场景压成一片黑。
  - *崩塌阶梯*：**保留暖色相**（橙、粉、紫红）的 16 色和 8 色子集，否则第一步就会让画面变红。然后是 4 种灰蓝、2 个色调、褪色。
- **光照就是索引步进**：`LIGHT[]` / `DARK[]` 表把每个索引沿其色阶移动一步。火把光晕、月光和火光是由 `LIGHT[LIGHT[c]]` / `LIGHT[c]` 构成、经 Bayer 阈值处理的光环。8-bit 场景中的火光用**暖色重映射**（绿 → 棕 → 锈），而不是普通提亮——普通提亮会把草地变成放射性的绿。
- **抖动**：渐变和光晕用 4×4 Bayer。光束用平铺的 50% 棋盘格加 25% 的边缘，读起来比渐变更干净。
- **视差**（横向卷轴）：带拱窗的远墙 0.35×，挂着旗帜和火把的柱廊 0.7×，带伪透视接缝的地面 1×，黑色前景柱子 1.6×。
- **精灵**：一套**绑定**（胶囊形肢体，左上方光源的三色阴影，每个部件内侧用该材质最暗色的线条，全局 1 px 墨色描边）加上**手工摆放的 ASCII 头部**。一套绑定给出所有姿势：行走 ×4、攻击、受伤、抬头看、推、坐、跪、背面推。8-bit 场景用同一套绑定，但**去掉高光色**。给勇者一个**剪影标志**：一条长围巾，尾端以 **3 帧步进循环**飘动，再加一撮翘起的头发。
- **头像** 32×32，3/4 侧面，基础脸 + 眼/眉和嘴的叠加层（平静、怅然、微笑、悲伤、坚定）。所有面部表演都由头像承担；34 px 的精灵脸只有一个像素的眼睛。
- **道具**：存档水晶是一个在 3D 中旋转的平面着色八面体，量化为 4 种受保护的青色（每 90° 8 帧），带抖动光晕。巨门是一扇正面的镶板石门，带旭日形门楣、拱石、开门时裂开的符文环，上方有一扇供向上俯仰的玫瑰窗。

## 标题、字幕与片尾卡

- **对话框就是字幕**，画在帧缓冲 y 134–176 处：
  - 三层圆角边框（墨 / 白 / 银）；
  - 蓝→藏青→夜色的抖动填充；
  - 左侧 32×32 头像；
  - 原创的不等宽像素字体（大写高 7，x 高 5，下伸 2），白色带 1 px 夜色阴影；
  - 随人声打字；打完显示 ▼。
- **皮肤随时代变化**：160×90 下 4 色的浅色框配深色文字；8-bit 的黑框配白边和 8-bit 头像；16-bit/当下为蓝色（随当下一起褪色，颜色回来时变得鲜艳）。
- 战斗信息放在顶部的细窗口里。每个框停留 ≥ 1.8 s 且 ≥ 人声 + 0.6 s。下一个框会切掉上一个。`.srt` 从同一个 `window.SUBS` 数组导出。
- **片名**：两行，2× 字体，8 邻域墨色描边，按行从白→银→钢的渐变，以 Bayer 溶解进出。**片尾卡**：金色片名，闪烁的 `▶ CONTINUE`，风格名称，`LemoLab × Claude Opus 5.5`，以及红围巾飘过一次。LemoLab 落款只属于本库的演示片：用户的影片不带 LemoLab 署名，也不复制这张卡片。

## 我们踩过的坑（演示片记录）

- **按排序的色板映射会把一切压成黑色**：主色板中暗色很多，分位数映射会把半个场景放进最暗的一级。按亮度加 gamma 映射（`lum^0.8`）。
- **不含暖色相的崩塌子集**会在第一步就把日落变成一片纯红。在 16 色和 8 色集中保留橙、粉和紫红。
- **没有深绿的 8-bit 色板**：夜晚的草地变成了蓝色。**篝火周围的普通提亮**把草地变成了霓虹绿。用暖色重映射。
- **把全彩场景后期量化成 4 级是一团泥**。以半分辨率、用 4 个已知索引原生绘制 4 色场景。
- 画成光滑圆顶的头发看起来像头盔。用交替单像素画的后发看起来像锯齿噪点；用 2–3 个大尖角。奶油色的束腰外衣看起来像裸露的皮肤。前手握着的法杖在侧视图中会横过脸；改用后手握在身后。背在背上的剑横过了躯干正面；改用挂在腰间的剑鞘。
- 深色木板门看起来像监狱。用带斜角、从左上方受光的凹嵌镶板，加上门钉、环形把手和门楣。一个 bug 把关着的门的中缝画成了亮色。
- **负数取模**：当相位偏移使 `t` 为负时，`Math.floor(t*12) % 4` 是负数，它索引到了 `undefined`。用 `((n % m) + m) % m`。
- **同音词**：whisper 把 "inn" 听成 "in"。通过 `asr` 字段接受它；字幕会消除歧义。
- 对话框遮住底部 25%。把地面线放在 y 128，让站立的角色保持在它上方。
- 在受保护颜色上做匹配剪辑时，要计算两个画面位置。演示片中的围巾在两个时代里都位于 (197, 104)。

## 构建说明

```
styles/pixel-rpg/demo/
  px.js        indexed framebuffer, palettes & LUTs (full/nes/gb4/faded/c16/c8/c4/c2), dither, mosaic
  font.js      variable-width pixel font      ui.js        windows, dialog, menus, file list, status, save
  sprites.js   rig + ASCII heads, scarf tails portraits.js 32×32 portraits + expressions
  props.js     crystal, halo, pedestal, door  memsprites.js 4-color kid sprites
  scenes.js    corridor (parallax), door tilt, LIGHT/DARK index lighting, torches
  memscenes.js village (160×90), campfire (8-bit), battle (16-bit), thumbnails, title, end card
  main.js      director: shots, transitions, palette timing, EV (sound events), SUBS
  timeline.json single source of timing (music, picture, mix)   lines.json voice script
  music/score.py original chiptune from timeline.json            mix.py foley + voice + ducking
  sheet.js     model sheet (?sheet=1)          tools/subs.mjs srt export      build.sh one-shot rebuild
```

1. 先写 `timeline.json`：段落、BPM、强拍、击点、静默、崩塌阶梯。音乐、画面和混音都读取它。
2. `?sheet=1` → 模型表；`?frame=corridor|door&lut=faded` → 在排布镜头之前用环境自检帧检查。
3. `core/tts/tts.py` → `asr_check.py`（全部 OK），然后对照时间线编写 `music/score.py`（交给一个并行的子代理效果很好）。
4. `node core/render/still.mjs demo --range 0.3:54.3:1.5` → `sheet.py` 总览；逐帧检查关键时刻。
5. `events.mjs` → `mix.py` → `tools/subs.mjs` → `video.mjs --workers 3`（1308 帧约 20 s）→ `mux.sh … 24 0`。
6. `sh demo/build.sh` 从零重现一切。
